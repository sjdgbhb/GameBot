## 核心函数/类变更

### orchestrator.py

- **`_restart_member`**: 重启前清理旧 `subprocess.Popen` 对象 — `kill()` 终止残留进程、`wait(timeout=3)` 回收、`stdout.close()` 关闭管道，异常时 warning 不中断。
- **导入**: `from typing import List` → `from typing import Dict, Optional`（`List` 已移除）。

### team_flow.py

- **`_build_business_objects(member)`** (新增): 首次构建 `GameUI`/`SceneNavigator`/`CombatHelper`/`EndlessRunner` 后缓存到 `member._jiubing2_biz`，后续调用直接复用。
- **`preparation`**: 合并 `member.task_cfg` 与 `member.member_cfg`（成员配置优先），`args` 中的 `difficulty` 最高优先覆盖。

### leader.py

- **`_wait_followers_ready`**: 优先按 `target_player` 名字匹配 OCR 识别到的"已准备"行；OCR 未识别到任何队员名字时回退按关键词数量判断。新增 `matched_names` 集合追踪已匹配队员。

### base.py

- **`_sync_exit`**: 非同步源等待超时从 `team_cfg.sync.exit_wait_timeout` 读取（默认 300s），轮询循环中检测 `stop_event` 实现提前退出。
- **`_create_dm` / `_create_war3` / `_create_kk`** (新增): 工厂方法封装 `DmClient`/`War3Business`/`KKBusiness` 实例化，子类或测试可覆盖以注入 mock 对象。

## 涉及配置

| 配置项 | 路径 | 说明 |
|--------|------|------|
| `sync.exit_wait_timeout` | `src/GameBot/config/data/team/team_task.toml` | 非同步源等待退出信号超时（秒），默认 300 |

## 影响范围说明

- **orchestrator.py**: 仅影响同步源子进程重启路径，正常流程不受影响。
- **team_flow.py**: `preparation` 和 `task_module` 均受益于业务对象缓存，行为不变但性能提升。配置合并逻辑变更可能影响未在 `member_cfg` 中配置 `difficulty` 的场景 — 现在会从 `task_cfg` 继承。
- **leader.py**: 准备状态检测逻辑增强，不影响原有数量判断回退路径。
- **base.py**: 工厂方法提取为纯重构，不改变运行时行为。`_sync_exit` 超时配置化后，未配置 `exit_wait_timeout` 的场景仍使用默认 300s，向后兼容。

## 待回归验证项

1. **`_restart_member` 旧进程清理**: 验证同步源崩溃重启后旧进程被正确 kill 且无 stdout 管道残留。
2. **`preparation` 配置合并**: 验证 `member_cfg` 中未配置 `difficulty` 时从 `task_cfg` 继承，`args` 覆盖优先级最高。
3. **`_wait_followers_ready` 玩家名匹配**: 验证 OCR 能识别到队员名字时按名匹配，无法识别时回退数量判断。
4. **`_sync_exit` 配置化超时**: 验证 `exit_wait_timeout` 配置生效，`stop_event` 触发时非同步源能提前退出等待。
5. **工厂方法 mock**: 验证测试中覆盖 `_create_dm` 等方法后能正确注入 mock 对象，不影响生产环境实例化。
