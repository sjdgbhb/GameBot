# GameBot 文档中心

本目录是 GameBot 项目的文档入口。文档按「分层 + 按模块解耦」组织，目的是：

1. **迭代开发不影响其他模块** —— 每个模块有独立的文档卡片，明确职责边界和依赖关系
2. **vibecoding 顺畅省上下文** —— 开发某模块时，只需加载该模块卡片 + 架构总览，无需读全量文档
3. **把控架构、与 AI 对齐** —— 架构层提供全局视角，领域层提供项目背景，减少 AI 猜测

## 模块卡片阅读约定

每个模块卡片遵循统一结构：

| 小节 | 内容 |
|------|------|
| **职责** | 这个模块做什么，在架构中的角色 |
| **对外能力** | 向其他模块提供什么能力（自然语言描述） |
| **依赖关系** | 依赖哪些其他模块 / 外部组件 |
| **关键约束** | 线程安全、进程隔离、环境要求等需要注意的特性 |
| **配置约定** | 从哪里读配置、关键配置项语义 |
| **禁忌** | 不应该做什么、容易踩的坑 |
| **关联文档** | 相关的架构、领域、任务文档链接 |

> **原则**：模块卡片用自然语言描述职责和能力，不堆砌类名/方法签名/实现细节。
> 这样文档不会因源码重构而失效。具体实现请读源码。

## 文档维护原则

1. **模块卡片不写实现细节** —— 只写职责、能力、依赖、约定，不贴代码
2. **架构文档保持稳定** —— 反映设计意图，不随实现细节变动
3. **领域知识独立维护** —— 游戏机制/平台特性/插件能力单独成文，不混入模块文档
4. **变更记录在 change_logs/** —— 重大变更写变更日志，不直接改架构文档
