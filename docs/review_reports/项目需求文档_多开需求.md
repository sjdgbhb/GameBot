# 项目需求文档 — 多开需求

> 日期：2026-08-15 | 作者：PM
>
> 本文档整合以下两大多开相关需求的 PRD 内容：
> - 无尽任务优化（多开窗口识别、自动创建房间、KK 弹窗处理等）
> - 通用组队任务框架（队长-队员多开组队协作）

---

## 一、需求背景

### 1.1 无尽任务优化背景

无尽任务（单局/多局）在长时间运行中遇到以下问题：

- BOSS 死亡提示（"开始挑战"）检测超时后，无法判断实际状态，影响后续循环。
- 直接调用 `quit_game` 未先确认 War3 窗口是否存在，窗口已消失时会执行无效退出。
- KK 平台在启动/房间阶段会出现非目标弹窗，遮挡目标窗口，导致点击失败。
- 多局任务依赖已有 KK 房间，未找到房间时无法自动创建。
- 多账号/多开场景下存在多个 War3 或 KK 窗口，脚本无法识别正确目标窗口。

### 1.2 通用组队任务框架背景

- 现有脚本仅支持单玩家单窗口运行，无法在多 KK 账号/多开场景下组队协作。
- 用户希望一套通用的组队任务框架：一主多从架构，队长建房、队员跟进、一键启动，进入游戏后各成员可独立执行不同任务，同时保持必要的同步。
- 现有 KK 多开识别能力（大厅/房间 OCR、War3 加载页 OCR）已具备，但缺少队长-队员协同、房间号共享、队员自动入房、游戏内分任务编排与同步机制。

---

## 二、目标用户与使用场景

- 用户同时开启多个 KK 平台账号（多个独立客户端）。
- **单任务多开场景**：多开 War3/KK 窗口时，脚本能根据玩家 ID 自动识别并绑定正确窗口。
- **组队协作场景**：通过一份组队任务配置文件定义队伍成员及其各自任务，一键启动组队脚本。
  - 队长（主）负责建房、选难度、开始游戏、退出游戏。
  - 队员（从）自动加入队长房间、进入游戏、选英雄、英雄就位后各自执行配置的任务、退出游戏。
  - 所有成员与同步源保持生命周期同步：同步源退出本局时全员同步退出，回到房间继续下一局。

---

## 三、关键术语

- **队长（Leader / 主）**：组队中的主控角色，负责 KK 建房、选难度、开始游戏、退出游戏，通过 IPC 广播状态。
- **队员（Follower / 从）**：组队中的受控角色，接收队长共享的房间信息加入房间，进入游戏后独立执行配置任务、退出游戏。
- **组队任务（team_task）**：通用组队任务，非无尽专属，任何游戏内任务均可组队。
- **组队配置文件**：`src/GameBot/config/data/team/team_task.toml`，定义队伍成员、各自 `target_player`、流程编排（flow）、同步规则等。
- **进程间通信（IPC）**：文件 IPC（`room_info.json` / `game_state.json` / `exit_signal.json` / `stop_signal.json` / `progress/*.json`），原子写入 + 轮询读取。
- **建房流程**：队长在大厅通过地图搜索，进入相应地图界面，点击创建房间按钮，在弹窗的窗口输入密码，点击创建。
- **入房流程（JoinRoomById）**：队员在大厅通过地图搜索+房间号+密码加入指定房间的可复用模块。
- **英雄就位模块（PositionInitializer）**：将英雄从准备阶段出生点移动到目标任务起始点的可选前置步骤。
- **流程编排（flow）**：每个成员的游戏内流程按 `preparation` → `position_init` → `task_module` → `pre_exit` 四阶段编排。
- **单局任务**：所有游戏内任务均视为单局任务，跨局循环由组队框架负责。
- **同步源（sync_source）**：由配置 `sync.sync_source` 显式指定的成员，决定全队本局退出时机。
- **target_player**：多开时用于识别目标窗口的玩家 ID 配置项。

## 四、功能目标

### 4.1 无尽任务优化

#### 必须实现

1. **BOSS 死亡提示超时处理**
   - `_wait_boss_dead` 在 `boss_death_timeout` 内未检测到 `boss_death_text` 时，保存当前屏幕截图。
   - 组队模式下，按照组队规则，非组队模式下，单局无尽停止任务，多局无尽正常退出 War3，继续下一局。

2. **退出游戏窗口存在性检查**
   - `quit_game` 执行退出逻辑前，先确认目标 War3 窗口存在。
   - 窗口存在：执行 F10→E→Q 退出流程。
   - 窗口不存在：保存当前屏幕截图，日志记录"目标窗口已消失，跳过退出逻辑"，直接返回，不抛异常。

3. **KK 弹窗检测与关闭**
   - 在 KK 大厅和创建房间流程中，周期性扫描可见的 KK 类弹窗。
   - 弹窗判定不依赖当前活动窗口是否为目标窗口，而是通过尺寸、标题、内容识别需要关闭的非目标弹窗。
   - 弹窗检测时机：进入地图主界面（点击地图后，显示该地图主界面，其下方有创建房间按钮）、退出游戏后，循环关闭小尺寸、非受保护的弹窗，直到没有可关闭的弹窗。
   - 必须识别并保留创建房间弹窗。

4. **KK 房间缺失时自动创建房间**
   - 多局任务或组队多局任务中，`KKBusiness.start_game` 未找到 KK 房间窗口时，触发自动创建房间流程。
   - 流程：搜索地图名 → 点击搜索结果 → 等待地图详情页 → 点击创建房间 → 输入密码 → 创建。
   - 创建房间逻辑需封装为可复用模块。

5. **多开目标窗口自动识别**
   - 检测到两个及以上相同 War3 或 KK 窗口时，通过以下规则识别并选择目标窗口：
     - **KK 大厅**：点击头像旁图标展开下拉框，OCR 识别玩家 ID，匹配当前账号。
     - **KK 房间**：在各自区域ocr识别出是否为房主、用户名。
     - **War3**：通过游戏加载页面的玩家列表，判断该窗口属于排在最前面的玩家用户名。
     - **KK 父子窗口关系**（如存在）：作为辅助手段区分不同玩家的相同 KK 窗口。
   - 绑定操作前必须确认目标窗口归属，避免误操作。

#### Nice-to-have

- 创建房间配置支持未来其他多局任务复用。
- KK 弹窗检测机制可扩展至其他平台弹窗类型。

### 4.2 通用组队任务框架

#### 必须实现

1. **一主多从架构与一键启动**
   - 通过一份组队任务配置文件定义整个队伍。
   - 一键启动一个组队脚本入口（`team_task`），脚本根据配置文件自动拉起队长与若干队员的独立子进程。
   - 队长为进程主控，队员为从属进程。
   - 队长通过 IPC 将房间号、密码通知所有队员。

2. **可复用的队员入房模块（JoinRoomById）**
   - 队员接收队长共享的房间号+密码后，在 KK 大厅自动进入房间：搜索地图名 → 点击"房间列表" → 输入房间号 → 点击搜索 → 双击结果 → 输入密码 → 确认。
   - 该流程封装为可复用模块。

3. **房内准备与进游戏**
   - 进入房间后，队员自动点击"准备/取消准备"按钮，等待队长开始游戏。
   - 队长确认所有队员准备完成后（可配置最大等待时间），点击开始游戏。
   - 所有成员进入 War3 后，各自使用 `target_player` / `player_id` 识别并绑定自己的 War3 窗口。

4. **游戏内准备阶段与分任务执行**
   - 游戏加载完毕后，队长负责选择难度。
   - 地图初始化完毕后，所有队员各自选英雄、学习技能、装备卡牌等（准备阶段）。
   - 各成员先执行英雄就位（如配置了就位模块），然后各自执行配置的游戏内任务：原地挂机、钓鱼、单局无尽、巡逻拾取等。
   - 组队中的无尽任务使用单局无尽，每局结束后退出 War3 并回到房间继续下一局。

5. **同步规则**
   - 同步源由用户在 `team_task.toml` 中通过 `sync.sync_source` 显式指定（默认队长），运行时不做动态选取。
   - 同步源完成/失败本局时，通过 `exit_signal.json` 广播，全员同步退出本局。
   - 非同步源成员任务失败时，仅该成员停止当前任务、退出本局并等待下局，不影响其余队员继续本局。

6. **循环下一局**
   - 所有游戏内任务均为单局任务，跨局循环由组队框架负责。
   - 同步源本局完成或失败时，全队退出游戏；所有成员回到房间继续下一局（房间意外关闭则队长重建、队员重新加入）。
   - 非同步源成员失败时，仅该成员退出本局并等待下局，其余队员继续本局。
   - 连续失败次数达到阈值（`sync.safe_stop_threshold`）时，任务安全停止并记录日志。

7. **多开窗口识别**
   - 队长与队员各自使用独立的玩家 ID / `target_player` 配置绑定正确的 KK 大厅、KK 房间、War3 窗口。
   - 队长与队员均通过 War3 加载页 OCR 确认各自 `target_player` 窗口。

8. **退出游戏**
   - 需支持配置退出前需做的事情（如存档，游戏开始前三分钟不可存档）。

9. **配置化**
   - 所有新坐标、超时、地图名、房间搜索路径、IPC 参数、任务选择、同步规则等均写入 TOML 配置，不硬编码。

10. **向后兼容**
    - 现有 `endless`、`fishing`、`patrol_loot` 等任务在未启用组队模式时行为不变。
    - 现有 `create_room` 等模块在不被组队脚本调用时行为不变。

11. **浮窗进度汇总**
    - 仅入口进程显示浮窗，汇总显示各成员任务进度（`task_progress`，如 `round=3/10`）。
    - 各子进程通过 `progress/*.json` 上报进度，按成员聚合。

#### Nice-to-have

1. **英雄就位模块**：编写各任务初始站位模块，当队员选择的游戏内任务对英雄初始站位有要求时，执行任务前先执行英雄就位模块。
2. **各队员流程编排**：每个成员通过 `flow` 配置编排游戏内流程，支持内置动作类型（wait / skill / item / msg / center）与 module 调用。
3. **多队员支持**：一个队长可同时带多个队员（同一房间），状态广播给所有已注册队员。
4. **通用组队任务框架扩展**：组队框架不仅用于九种兵器2，也可供其他地图/游戏复用。

## 五、用户旅程

### 5.1 队长旅程

1. 用户在 KK 客户端 A 登录队长账号。
2. 一键启动组队脚本，脚本读取组队配置文件，识别自身为队长角色。
3. 脚本进入大厅，搜索地图，创建密码房间。
4. 脚本通过 IPC 广播 `room_id` + `password`。
5. 等待所有队员准备完成（或超时），开始游戏，进入 War3。
6. 选择难度，等待地图初始化完毕。
7. 选择英雄（准备阶段）。
8. 执行队长配置的游戏内任务。
9. 如为同步源，本局完成或失败时通过 `exit_signal.json` 通知全员退出；否则等待退出信号，停止当前任务，执行 `pre_exit` 动作（如存档），退出游戏。
10. 进入下一局，重复 3-10。

### 5.2 队员旅程

1. 用户在 KK 客户端 B 登录队员账号。
2. 一键启动组队脚本，脚本读取组队配置文件，识别自身为队员角色。
3. 监听队长状态，收到房间信息后执行 `JoinRoomById` 入房。
4. 点击准备，等待队长开始游戏，进入 War3。
5. 等待队长选难度、地图初始化完毕后，执行流程编排。
6. 如为同步源，本局完成或失败时通知全员退出；否则等待退出信号，停止当前任务，执行 `pre_exit` 动作，退出游戏。
7. 收到下局房间信息后，重复 3-7。

## 六、同步规则详解

### 6.1 同步源

- 同步源由配置 `sync.sync_source`（`target_player`）显式指定，默认队长；运行时不做动态选取。
- 所有游戏内任务均为单局任务，跨局循环由组队框架负责。

### 6.2 同步事件

- **本局退出**：同步源完成或失败退出本局时，写 `exit_signal.json` 通知所有成员退出。
- **下局开始**：全员回到房间继续下一局；房间意外关闭则队长重建房间并重新广播 `room_info.json`，队员重新入房并准备。
- **任务停止**：入口进程停止整个组队任务时，写 `stop_signal.json` 通知所有成员停止。
- **同步源崩溃**：入口进程监控子进程，同步源崩溃时自动重启（最多 `sync.max_restart` 次），超限停止全部成员；非同步源崩溃仅告警。

## 七、边界与异常处理

- **IPC 失败**：记录 error，跳过本局。
- **队员未找到房间或无法加入房间**：记录错误、截图，队长重新建房，队员重新尝试加入；连续失败达到阈值后终止该队员进程。
- **队长意外退出房间**：队长重新建房，队员重新加入。
- **多 War3/KK 窗口**：未匹配到 `target_player` 的窗口时，跳过本局，该玩家停止运行其任务脚本，不点击非目标窗口。
- **同步源本局失败**：触发同步退出（`exit_signal.json`），所有成员退出，进入下一局。
- **非同步源成员本局失败**：仅该成员停止任务、退出本局并等待下局，不影响其余队员。
- **同步源子进程崩溃**：入口进程自动重启同步源（超过 `sync.max_restart` 次则停止全部）；非同步源崩溃仅告警。
- **英雄就位失败**：就位模块失败时，队员本局任务失败，按跳过本局处理。

## 九、新增/变更配置项

### 9.1 无尽任务优化

- `kk.toml` 新增 `[kk.hall]`、`[kk.create_room]`、`[kk.multi_instance]` 配置段
- `war3.toml` 新增 `[war3.multi_instance]` 配置段
- `endless.toml` 新增 `target_player` 配置项
- `endless_single.toml` 新增 `boss_death_text` / `boss_death_timeout` 配置项

### 9.2 通用组队任务框架

- 组队任务配置文件 `src/GameBot/config/data/team/team_task.toml`（`name = "team.team_task"`，`extends = ["kk", "war3"]`）：
  - `[this.game]`：地图名（`map_name`）
  - `[this.ipc]`：轮询间隔、IPC 目录、准备超时、入房重试次数/间隔
  - `[this.sync]`：连续失败停止阈值、进度上报间隔、同步源、同步源最大重启次数
  - `[[this.members]]`：每个成员定义 `role`、`target_player`、`flow`（四阶段编排）
  - `[float_window]`：浮窗标题
- 扩展 `kk.toml`：`[kk.join_room]`（房间列表按钮、房间号输入框、搜索图标等坐标）、房间号/准备状态 OCR 区域

## 十、已决事项

- IPC 机制：文件 IPC（JSON 原子写入 + 轮询），毫秒级延迟满足秒级同步精度要求，兼容 32 位大漠 Python 3.8 环境。
- 房间号获取：房间窗口左上角 OCR 读取；准备状态由队长 OCR 识别各楼层，不通过 IPC 上报。
- 同步源判定：动态判定已废弃，改为配置 `sync.sync_source` 显式指定（默认队长）。
- 多局/单局区分：已移除，所有游戏内任务均为单局任务，框架负责循环下一局。
- 父子窗口关系：KK 主界面与房间之间无父子关系（均为独立顶层窗口）；弹窗与主界面存在父子关系。多开区分主要依赖 PID + OCR。
