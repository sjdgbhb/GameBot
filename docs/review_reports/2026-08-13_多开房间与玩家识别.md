# 需求评审报告 — 多开窗口定位与KK房间玩家识别/操作
> 日期：2026-08-13

## [Dev] 需求评审 — 实现方案

### 功能目标

解决以下 6 项需求：
1. **窗口定位改进**：不再依赖活动窗口（前台窗口）作为目标窗口，改为按窗口类名/标题枚举查找；非多开时直接使用查找到的窗口
2. **KK房间玩家识别**：识别房主（1楼）和非房主（2~6楼），通过按钮文字区分角色和状态
3. **F11盟友列表反推**：游戏内按F11显示盟友列表（不含自己），排序与房间楼层一致，可反推当前War3窗口归属的玩家
4. **后台OCR可靠性**：确保后台运行时图色OCR准确可靠
5. **KK弹窗自动关闭**：所有KK平台弹窗一律自动关闭，不区分归属
6. **房间操作逻辑**：房主等全准备后点开始；非房主进房自动准备；退回房间后自动重新准备/开始

### 核心函数/类设计

#### PlayerIdentifier

```python
class PlayerRole(Enum):
    HOST = "host"        # 房主（1楼）
    MEMBER = "member"    # 非房主（2~6楼）

class ButtonState(Enum):
    READY = "ready"              # 准备（可点击）
    CANCEL_READY = "cancel_ready" # 取消准备（已准备状态）
    START_GAME = "start_game"    # 开始游戏（全准备）
    WAIT_READY = "wait_ready"    # 等待准备（有人未准备）
    IN_GAME = "in_game"          # 游戏中（灰色）

class PlayerIdentifier:
    def __init__(self, dm, kk_cfg, war3_cfg): ...
    
    def identify_role(self, room_hwnd: int) -> PlayerRole:
        """OCR识别房间按钮文字，判断房主/非房主。
        房主按钮关键词：开始游戏/等待准备/游戏中
        非房主按钮关键词：准备/取消准备/游戏中
        """
    
    def get_button_state(self, room_hwnd: int) -> ButtonState:
        """OCR识别当前按钮状态。"""
    
    def identify_floor_by_f11(self, war3_hwnd: int) -> int:
        """游戏内按F11打开盟友列表，OCR识别自己在列表中的位置。
        盟友列表不含自己，排序与房间楼层一致。
        列表中第N个盟友 = 自己是第N+1楼。
        返回楼层号（1=房主，2~6=非房主）。
        """
    
    def count_players(self, kk_room_hwnds: List[int], war3_hwnds: List[int]) -> int:
        """统计当前玩家数 = KK房间窗口数 + War3窗口数。"""
```

#### RoomOperator

```python
class RoomOperator:
    def __init__(self, dm, kk_cfg, player_identifier): ...
    
    def execute_room_flow(self, room_hwnd: int, role: PlayerRole) -> bool:
        """房间操作主流程：
        1. 关闭所有KK弹窗
        2. 非房主：自动点准备
        3. 房主：等待全准备后点开始游戏
        """
    
    def auto_ready(self, room_hwnd: int) -> bool:
        """非房主自动准备：按钮为'准备'时点击，'取消准备'时保持。"""
    
    def wait_all_ready_and_start(self, room_hwnd: int, timeout: int = 120) -> bool:
        """房主等待全准备后点开始：
        循环检测按钮状态：
        - '等待准备' → 继续等
        - '开始游戏' → 点击
        - '游戏中' → 已开始，返回
        """
    
    def wait_buttons_recover(self, room_hwnds: List[int], timeout: int = 30) -> bool:
        """退回房间后等待所有玩家按钮恢复（灰色消失）。"""
    
    def re_enter_room_flow(self, room_hwnd: int, role: PlayerRole) -> bool:
        """退回房间后的重新准备/开始流程：
        1. 等待按钮恢复
        2. 非房主：自动重新准备
        3. 房主：等待全准备后点开始
        """
    
    def dismiss_all_kk_popups(self) -> None:
        """关闭所有KK弹窗，不区分归属。
        枚举所有KK类名窗口，关闭尺寸小于房间的弹窗。
        """
```

### 后台OCR可靠性分析

当前 OCR 架构已支持后台运行：
- OCR 通过 `inference/client.py` 子进程执行（主环境 Python 3.12）
- 子进程通过截屏 API 获取指定区域图像，不依赖窗口前台状态
- `_compute_ocr_bbox` 使用大漠 `GetClientRect` 计算屏幕坐标，传给 OCR 子进程

**需验证项**：
- 大漠 `BindWindow` 使用 `display="normal"` 模式，后台绑定时图色获取是否正常
- 如果后台图色不准确，可能需要改用 `display="gdi"` 模式（GDI 模式兼容后台截图）
- 需在 `bind_window` 调用处增加 display 模式可配置化（从 war3_cfg 读取）

### 多开窗口定位策略

1. **非多开（单窗口）**：`find_all_windows()` 返回1个窗口 → 直接使用，不要求前台
2. **多开（多窗口）**：`find_all_windows()` 返回多个窗口 → 需要通过F11盟友列表识别每个War3窗口归属的玩家
3. **KK房间窗口**：通过窗口尺寸区分房间窗口和弹窗，枚举所有KK类名窗口

### 窗口操作流程（endless.py 集成）

```
原流程：do_kk() → kk.start_game() → 直接点开始按钮
新流程：do_kk() → room_operator.execute_room_flow() →
  1. dismiss_all_kk_popups()  # 关闭所有KK弹窗
  2. identify_role()          # 识别当前窗口是房主还是非房主
  3. if 非房主: auto_ready()   # 自动准备
  4. if 房主: wait_all_ready_and_start()  # 等全准备后开始
  5. 等待进入War3
```

退回房间后：
```
  1. wait_buttons_recover()   # 等待按钮恢复
  2. re_enter_room_flow()     # 重新准备/开始
```
