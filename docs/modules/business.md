# 业务逻辑层

> 源码位置：`src/GameBot/runner/business/`

## 职责

业务逻辑层把游戏操作封装为可复用的「原语」，供任务编排层调用。
它是项目的核心：知道怎么找窗口、怎么移动、怎么放技能、怎么识别游戏状态、
怎么操作游戏面板，但不关心任务流程的编排（循环几次、什么时候停）。

采用三级组合结构，从通用到特化：
- **业务基类**：提供跨平台通用能力（OCR、输入法切换）
- **KK平台业务**：KK 大厅/房间/多开相关操作
- **War3通用业务**：魔兽3窗口/输入/技能/文字监测
- **九种兵器2业务**：游戏面板/战斗/场景导航/无尽循环等地图专属操作

## 对外能力

### 业务基类
- 后台截图 → OCR 识别（统一入口）
- 美式键盘切换（输入前置）
- 统一的 sleep 和大漠可用性检查

### KK平台业务
- 大厅弹窗清理（按窗口类名/尺寸/OCR关键词关闭无关弹窗）
- 大厅窗口认领（多开场景下通过 OCR 玩家名找到属于指定账号的窗口）
- 房间管理（创建房间后点击开始游戏、房间弹窗清理、掉线重连处理）
- 加入房间（按房间号+密码搜索并加入）
- 多开识别（按 PID 串行化、差分窗口查找与 OCR）

### War3通用业务
- 窗口管理（设置尺寸、等待窗口出现、判断是否进入游戏、退出游戏）
- 输入控制（移动/传送/背包物品/框选，所有等待支持停止事件中断）
- 技能控制（单技能施放、连招执行，支持地面/敌方/友方/自身目标类型）
- 文字监测（OCR 等待特定文字、一次性文字 watcher、常驻文字监测线程）

### 九种兵器2业务
- 游戏面板操作（学习技能、选难度、选英雄、读存档、装备卡牌/神碎/圣痕、折叠属性面板）
- 战斗辅助（技能池解析、连招执行、宠物喂食、物品栏快捷键查找、路线点行为执行）
- 场景导航（进入皇宫、传送到森之城/巡逻区域、从皇宫进入无尽）
- 无尽循环（准备阶段全流程、按楼层循环刷怪、BOSS死亡检测、刷新计时）
- 附近清理（概率性发送清理地面物品的聊天指令，无后台线程）
- 组队步骤基类（九兵默认准备阶段实现，供组队任务复用）

## 依赖关系

- **驱动层**：大漠客户端（截图/输入/窗口/找图找色）
- **推理模块**：OCR 文字识别、（间接）宝箱检测/战斗状态检测
- **配置系统**：通过依赖注入接收配置段（war3段、hero段、完整闭包等）
- **共享工具**：日志、异常（StopTaskError 等）

### 内部层次
```
业务基类（OCR/输入法/sleep）
  ├── KK平台业务（mixin组合：大厅+房间+加入+多开）
  └── War3通用业务（mixin组合：窗口+输入+技能+文字监测）
        └── 九种兵器2业务（对象组合：面板+战斗+导航+无尽+清理+组队步骤）
```

- KK 和 War3 同级，都继承自业务基类，KK 不依赖 War3
- War3 用 mixin 多继承组合四个能力模块
- 九兵业务用对象组合（互相持有引用），在任务层显式装配

## 关键约束

### 文字监测线程
- 常驻文字监测在脚本运行期间以后台线程运行，按固定区域用 OCR 持续识别
- 用于事件中断移动等待（如检测到「已完成」时立即中断行走）
- 注意：大漠 COM 非线程安全，文字监测用 OCR 子进程而非大漠 COM

### 停止事件
- 所有输入操作的等待都支持 `stop_event` 中断
- 被中断时抛出 `StopTaskError`，任务循环捕获后优雅停止

### 配置注入
- 业务对象在构造时接收配置段（不自己调用 config.load_task）
- War3Business 接收 war3 配置段
- GameUI/CombatHelper 接收 war3/hero/完整闭包 + War3Business 引用
- 物品快捷键从英雄配置的 inventory 列表获取，不硬编码

## 配置约定

| 配置段 | 来源 | 语义 |
|--------|------|------|
| `war3.*` | war3.toml | 窗口设置、绑定模式、各种时间参数 |
| `hero.*` | heroes/*.toml | 英雄技能、物品栏、圣痕、卡牌、神碎配置 |
| `command.*` | jiubing2.toml | 游戏内聊天指令（清理附近/清理无尽/查询任务） |
| `game.*` | jiubing2.toml | 游戏基础设置（地图名、加载时间、传送时间等） |
| `stigmata.*` | jiubing2.toml | 圣痕系统参数 |
| `card.*` | jiubing2.toml | 卡牌系统参数 |
| `shard.*` | jiubing2.toml | 神碎系统参数 |
| `pet.*` | jiubing2.toml | 宠物系统参数 |
| `prompt_text.*` | jiubing2.toml | 屏幕提示文本 OCR 区域 |
| `atomic_task.*` | jiubing2.toml | 原子任务通用配置（接取/完成文本、监测间隔） |

## 禁忌

- ❌ 不要在业务代码中调用 `config.load_task` 或 `config.get`（通过依赖注入接收配置）
- ❌ 不要硬编码物品快捷键（从英雄配置的 inventory 获取）
- ❌ 不要硬编码坐标（从配置读取，坐标基于 war3.toml 的 client_size）
- ❌ 不要在文字监测线程中使用大漠 COM（用 OCR 子进程）
- ❌ 不要在业务对象中包含任务循环逻辑（循环编排是任务层的事）
