# 大漠驱动层

> 源码位置：`src/GameBot/runner/driver/` + `src/GameBot/dm_bridge/`

## 职责

驱动层是项目与游戏窗口交互的「手和眼」。它屏蔽了大漠插件 COM 只支持 32 位 Python 的限制，
向上层提供一套统一的大漠客户端接口（截图、输入、窗口管理、找图找色），
底层通过 RPC 桥接子进程把调用转发到 32 位环境执行。

由两部分组成：
- **驱动层**（`runner/driver/`）：运行在主环境 3.12，是大漠客户端的抽象与 RPC 客户端
- **桥接子进程**（`dm_bridge/`）：运行在 32 位 Python 3.8，实际创建和调用大漠 COM 对象

## 对外能力

驱动层向业务逻辑层提供以下能力（通过大漠客户端对象）：

- **窗口管理**：查找/枚举窗口、绑定/解绑窗口（上下文管理器）、获取窗口矩形和状态、
  客户区坐标与屏幕坐标转换、layered 窗口强制刷新
- **截图**：区域截图（支持 layered 窗口的 PrintWindow 降级路径）、临时截图供 OCR 使用
- **输入**：键盘按键、鼠标移动/点击/双击、向窗口发送字符串
- **视觉**：找图（按名称在资源目录查找 BMP 模板）、找色、取色
- **调试截图**：保存截图到日志目录（带频率控制，避免刷屏）

## 依赖关系

- **配置系统**：读取大漠 DLL 路径、版本、桥接 Python 路径
- **资源管理器**：解析找图用的 BMP 模板路径
- **共享工具**：日志、异常（DmError）
- **桥接子进程**：依赖 pywin32（COM）、大漠插件 DLL、ctypes（DPI感知/管理员提权）
- **PIL**：处理 PrintWindow 截图的图像数据

## 关键约束

### 进程隔离
- 主环境（3.12，64位）通过 RPC 调用桥接子进程（3.8，32位）
- 每个大漠客户端实例独占一个桥接子进程，多开时互不干扰
- 通信协议：stdin/stdout 行式 JSON（请求-响应模式）

### 线程安全
- 大漠 COM 是线程亲和的，所有 COM 调用在桥接子进程主线程串行执行
- 驱动层客户端通过锁串行化请求，多线程调用安全但会排队

### layered 窗口刷新（重要）
- KK 平台 Qt 窗口是 `WS_EX_LAYERED`，后台输入/点击后画面不刷新
- 解决方案：临时取消 layered 样式 → RedrawWindow → 恢复 layered
- **约束**：此操作会破坏大漠后台绑定状态，不能在 `bind_window` 上下文内调用
- **正确做法**：拆成两段 bind，在中间调用刷新

### 子进程不自动重启
- 桥接子进程异常退出时不自动重启，避免静默丢失窗口绑定状态
- 调用方会收到错误，需显式处理

### DPI 感知
- 主进程和子进程都声明 DPI 感知，保证坐标系一致
- 所有坐标基于客户区（非屏幕坐标），无需转换

## 配置约定

| 配置项 | 位置 | 语义 |
|--------|------|------|
| `dm.version` | base.toml | 期望的大漠插件版本 |
| `dm.dll_path` | base.toml | 大漠 DLL 所在目录 |
| `dm.python_path` | base.toml | 可选：32位Python路径（默认自动检测 .venv-dm） |
| `war3.bind_mode` | war3.toml | 绑定模式开关：foreground / background（顶层任务可用自身 [this].bind_mode 覆盖） |
| `war3.bind_foreground.*` | war3.toml | 前台绑定参数（normal 系截图/鼠标/键盘） |
| `war3.bind_background.*` | war3.toml | 后台绑定参数（dx2截图 + 后台鼠标/键盘，多开/遮挡用） |
| `paths.screenshot_path` | base.toml | 调试截图输出目录 |

## 禁忌

- ❌ 不要在 64 位主环境中直接创建大漠 COM 对象（会失败）
- ❌ 不要在 `bind_window` 上下文内调用 layered 窗口刷新
- ❌ 不要跨进程共享大漠客户端对象（每个实例独占子进程）
- ❌ 不要在桥接子进程中安装 Web/OCR/AI 依赖（仅 pywin32 + loguru）
- ❌ 不要假设子进程崩溃后会自动恢复（需调用方显式处理）
