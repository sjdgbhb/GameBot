# 模块依赖关系图

## 依赖关系总览

箭头表示「依赖于」，从上层指向下层。同层模块之间也可能有依赖（见下文）。

```
Web配置端 ─────────────┐
                        │
任务编排层 ────────────→│
                        ├──→ 业务逻辑层 ──→ 驱动层 ──→ 桥接子进程(3.8)
组队框架 ──────────────→│        │              │
                        │        ├──→ 推理模块   │
                        │        │              │
                        │        └──→ 配置系统   │
                        │                   ↑   │
                        └───────────────────┘   │
                                                │
                    共享工具 ←───────────────────┘
```

## 模块清单与依赖

### 配置系统（config/）
- **被依赖**：几乎所有模块（通过 `config.load_task` 或 `config.get`）
- **依赖**：共享工具（文件IO、日志）
- **边界**：只负责加载和合并配置，不包含任何业务逻辑

### 共享工具（utils/）
- **被依赖**：所有模块
- **依赖**：无（仅标准库 + loguru）
- **边界**：无状态工具，不依赖任何业务模块

### 驱动层（runner/driver/）
- **被依赖**：业务逻辑层、组队框架
- **依赖**：配置系统（读DLL路径/版本）、共享工具（日志/异常）、资源管理器（图片路径）
- **边界**：只提供大漠能力（截图/输入/窗口/找图找色），不包含游戏逻辑

### 桥接子进程（dm_bridge/）
- **被依赖**：驱动层（通过 RPC 调用）
- **依赖**：pywin32（COM）、大漠插件DLL
- **边界**：独立进程，仅 32 位 Python 3.8，不导入主环境任何模块

### 推理模块（inference/）
- **被依赖**：业务逻辑层（OCR文字识别、宝箱检测、战斗状态检测）
- **依赖**：配置系统（读模型路径/设备）、RapidOCR、ONNXRuntime
- **边界**：只做推理（输入图片→输出结果），不做截图（截图由驱动层或ImageGrab完成）

### 业务逻辑层（runner/business/）
- **被依赖**：任务编排层、组队框架
- **依赖**：驱动层、推理模块、配置系统、共享工具
- **内部层次**：
  - `base` → 业务基类（OCR能力、输入法切换）
  - `kk` → KK平台业务（建房/入房/弹窗清理/多开识别）
  - `war3` → War3通用操作（窗口/输入/技能/文字监测）
  - `war3/jiubing2` → 九种兵器2业务（面板/战斗/导航/无尽循环）
  - `war3/jiubing2` 依赖 `war3`，`war3` 依赖 `base`，`kk` 依赖 `base`
- **边界**：封装游戏操作原语，不包含任务循环逻辑

### 任务编排层（runner/tasks/）
- **被依赖**：CLI入口（main.py）、Web端（通过子进程启动）
- **依赖**：业务逻辑层、推理模块（OCR预热）、配置系统、共享工具、UI层
- **内部层次**：
  - `base` → 任务基类（窗口绑定/OCR预热/原子任务循环）
  - `atomic` → 原子任务（接取→完成→提交的最小单元）
  - `endless` / `reputation` / `others` / `achievements` → 具体任务
- **边界**：编排业务原语完成任务流程，不直接操作大漠COM

### UI层（runner/ui/）
- **被依赖**：任务编排层（浮窗入口）、组队框架（编排器浮窗）
- **依赖**：共享工具（StopTaskError）、pywin32/ctypes
- **边界**：只负责浮窗显示和停止键监听，不参与业务逻辑

### 组队框架（runner/team/）
- **被依赖**：组队任务入口（tasks/team/）
- **依赖**：业务逻辑层（KK/War3/九兵）、驱动层、配置系统、共享工具、UI层
- **边界**：多开协作的进程管理和IPC，游戏内流程委托给业务层和steps基类

### Web配置端（web/）
- **被依赖**：无（是顶层入口）
- **依赖**：配置系统（读写TOML/user_configs）、FastAPI、Vue前端
- **边界**：配置编辑和任务启动，不包含任务执行逻辑（通过子进程启动任务模块）

## 接口边界

### 配置系统 → 所有模块
- **接口**：`config.load_task(task_name) → dict`（返回完整配置闭包）
- **接口**：`config.get(path) / config.get_section(name)`（仅入口和工具模块使用）
- **约定**：业务代码不直接调用 `config.load_task`，只接收注入的配置dict

### 驱动层 → 业务逻辑层
- **接口**：大漠客户端对象（提供截图/输入/窗口/找图找色能力）
- **约定**：业务代码通过 `create_dm_client()` 创建客户端，在 `bind_window` 上下文内操作

### 推理模块 → 业务逻辑层
- **接口**：`get_inference_client()` 返回单例推理客户端
- **能力**：OCR文字识别、宝箱检测、战斗状态检测
- **约定**：模型懒加载，首次调用时初始化

### 业务逻辑层 → 任务编排层
- **接口**：业务对象（War3Business / GameUI / CombatHelper / SceneNavigator / EndlessRunner）
- **约定**：任务类在构造函数中创建业务对象，注入配置段

### 任务编排层 → CLI/Web
- **接口**：任务类的 `run()` 方法
- **约定**：任务模块有 `main()` 入口，调用 `load_task` 后实例化任务类

## 循环依赖检查

当前架构无循环依赖。依赖方向严格自上而下：

```
Web/CLI → 任务编排 → 业务逻辑 → 驱动层 → 桥接子进程
                   → 业务逻辑 → 推理模块
                   → 业务逻辑 → 配置系统
         → 组队框架 → 业务逻辑 → ...
所有层 → 共享工具
所有层 → 配置系统
```
